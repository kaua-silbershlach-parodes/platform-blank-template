# Machinery Blank Template

A desktop application template from **A Elite Estrangeira**, combining a Rust/Tauri 2 shell, the system WebView, signed GitHub auto-updates, and an optional local Elixir/OTP backend. The UI uses plain HTML, CSS, and JavaScript; no frontend bundler or npm dependency is required.

## Architecture

| Directory | Purpose |
| --- | --- |
| `src-tauri/` | Rust shell, Tauri configuration, NSIS installer, signature verification, and native capabilities |
| `ui/` | Desktop interface, current version, update check, signed download, and restart controls |
| `backend/` | Independent Elixir/OTP sidecar with a supervised health endpoint on `127.0.0.1:45900` |
| `scripts/` | Build, installation, and verification utilities |
| `tests/` | Update-feed validation and installed-app integrity checks |

The Rust shell provides the desktop window and integration with the operating system. Elixir remains an independent component for the backend, with its own version and supervision tree. Its health endpoint is bound to localhost, not exposed as a network service.

## Development

From the `src-tauri/` directory, with the Rust toolchain and Tauri CLI installed:

```text
cargo tauri dev
```

## Signed Windows installer

The Windows target is NSIS, installed per user without administrator rights. The build helper is:

```powershell
scripts\03-build-installer.ps1 -Drive 'F'
```

Change `-Drive` to the drive containing your working copy. The script creates or uses the local signing key stored under `%USERPROFILE%\.machinery-template\` and creates the signed installer and its `.sig` file in `src-tauri\target\release\bundle\nsis\`.

The updater public key is committed in `src-tauri/tauri.conf.json`; the private signing key stays outside the repository.

The signing key and executable identity are independent of the GitHub repository name. Renaming the application changes the installed product identity; existing older products should not be treated as compatible update targets without migration testing.

## Auto-updates

The application reads the signed update manifest at:

```text
https://raw.githubusercontent.com/kaua-silbershlach-parodes/platform-blank-template/main/machinery-blank-template/latest.json
```

Each Machinery Windows release uses a `machinery-v<version>` tag and publishes all three files:

- `Machinery.Blank.Template_<version>_x64-setup.exe` — NSIS installer (use the exact filename generated by Tauri).
- The corresponding `.exe.sig` signature.
- `latest.json` with the version and `windows-x86_64` platform entry pointing to that exact installer URL and its signature.

The updater verifies the signature against the public key built into the app, installs the update, and then offers a restart. Unsigned or incorrectly signed artifacts must be rejected.


## Backend

In `backend/`, run:

```text
mix run --no-halt
```

The minimal `MachineryBackend` OTP application serves `/health` from `127.0.0.1:45900`. The port may be overridden through `MACHINERY_BACKEND_PORT`. The sidecar has its own version and is not packaged into the installer by default.

## Project rules

- Keep the interface lightweight and the backend independently versioned.
- Preserve signed update verification; hashes alone do not authenticate a release publisher.
- Never place credentials or private keys in Git.
